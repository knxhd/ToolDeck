## 1. 项目概况

### 1.1 定位

一个**本地/私有部署的一体化 API 工作台**：HTTP 调试台 + Collections 管理 + 批量压测 + WebSocket + MCP 客户端 + LLM Playground，单文件分发（PyInstaller）或容器部署，多用户 + 团队共享。

### 1.2 技术栈（实测版本约束）

| 层 | 技术 |
|---|---|
| 前端 | Vue 3.5 + TypeScript 5.6（`strict: true`）+ Pinia 2 + Vue Router 4 + Arco Design Vue 2.58 + Monaco 0.52 + Vite 5 + Less 4 + `@kangc/v-md-editor` + highlight.js |
| 后端 | FastAPI + Pydantic v2 + httpx + MCP Python SDK + SQLite(WAL) |
| 打包 | PyInstaller onefile（`launcher{,-windows,-linux}.spec`）/ Docker（多阶段未做，单阶段） |
| 数据 | `~/.api-tool/`（`config.json` 遗留 + `api-tool.db` 主存储 + `files/` 上传副本） |

### 1.3 规模与产物

- 前端源码 65 个文件；后端 `app/` 约 40 个模块（路由 10 / schema 4 / service 22 / llm 子包 3）。
- 构建产物（2026-11-05 的过期 `dist`）实测体积：

## 3. 缺陷与优化点（按优先级）

### 3.1 🔴 P0·安全：一批接口完全没有鉴权

**证据**（这些 `@router` 装饰后没有 `Depends(current_user)`）：

- `backend/app/api/mcp.py:28,33,41,49,57,65,122,131` —— `GET/POST/PUT/DELETE /api/mcp/servers`、`/servers/{name}/test`、`/servers/{name}/tools`、`/ad-hoc/tools`、`/ad-hoc/call`
- `backend/app/api/llm.py:41,46,54,62` —— `/api/llm/providers` 全 CRUD
- `backend/app/api/files.py:84,103` —— `/api/files/pick`、`/api/files/upload`

**为什么是 P0**

1. `llm_store.list_providers()` 直接返回 `load_config()` 的结果，而 `load_config()` 会**解密** `api_key` → 匿名 `GET /api/llm/providers` 即拿到所有 Provider 的明文密钥。
2. `/api/mcp/ad-hoc/tools` 接受任意 `url + headers` 并由服务端发起请求 → **标准 SSRF**：可探测 `127.0.0.1` / `169.254.169.254` / 内网段，并把响应回吐给调用方；`/api/mcp/servers/*` 还能被匿名篡改。
3. `/api/files/upload` 无大小限制、无鉴权 → 任意人可向数据目录写文件、撑爆磁盘。
4. 部署形态鼓励 `--host 0.0.0.0` / Docker `0.0.0.0:8765`（README 明确写了「服务器上对外提供服务」），风险不是纯理论。

**建议**

- 在 `create_app()` 统一加一层：`app.include_router(api_router, dependencies=[Depends(current_user)])` 包住全部业务路由，仅放行 `/api/health`、`/api/auth/register|login`、`/api/users/check` 的白名单。
- `ad-hoc` 增加目标策略：默认禁止私网/回环/云元数据地址段（`ipaddress` 判定），需要时由配置显式开放。
- `files/upload` 增加最大体积、扩展名白名单与鉴权。
- `GET /api/llm/providers` 返回时把 `api_key` 掩码（前端已有 `maskApiKey`），仅在服务端保存时解密。

### 3.2 🔴 P0·功能失效：请求设置（超时/重定向/SSL）没有传给后端

**证据链**

1. `RequestSettingsDialog.vue` 把 `timeout / follow_redirects / verify_ssl` 写进 `tab.request`（类型定义齐全：`api/types.ts:44-48`）。
2. `frontend/src/utils/env.ts:250-266` 的 `resolveRequest()` 只返回 `{method, url, headers, params, body_type, body, auth}` —— **三个字段被丢弃**。
3. `stores/workbench.ts:266` 用 `{...resolved, url: baseUrl}` 作为 payload 发 `/api/http/stream`。
4. 后端 `api/http.py:83-92` 明明读的是 `req.timeout / req.follow_redirects / req.verify_ssl`，但永远拿到默认 `30 / False / True`。

→ 用户在界面上把超时改成 5 秒、勾上跟随重定向、关掉 SSL 校验，**行为完全不变**。

**建议**：在 `resolveRequest` 里透传三者（并保留 `placeholders` 之外的清理逻辑），或改为在 `workbench.send()` 里显式 `payload.timeout = tab.request.timeout ?? 30`。同时补一条「设置生效」的手工验收：超时设 2s 打一个 5s 慢接口，应立即出现超时错误。

---

### 3.3 🔴 P0·部署：Linux / Docker 缺 `cryptography`，保存集合直接 500

**证据**

- `Dockerfile:13-18` 只安装 `fastapi / uvicorn / pydantic / httpx / mcp`；`build-linux.sh:93-100` 同样只有这 5 个。
- `pyproject.toml` 把 `cryptography` 放在 **optional**（`secure`），未进默认依赖。
- `crypto.py` 在非 Windows 上依赖 Fernet（需要 `cryptography`）；`collection_store.save_collections()` 对每个节点的 headers 都调用 `crypto.encrypt()`（`collection_store.py:45-50,91-105`）。

→ 容器里第一次保存/修改集合就会抛 `RuntimeError`，前端看到 500。启动时的迁移又被 `try/except` 吞掉（`app/__init__.py:32-42`），所以现象是「能启动、但一保存就崩」。

**建议**

1. `cryptography` 提为硬依赖（或让 Dockerfile / 打包脚本装 `.[secure]`）；
2. `crypto` 增加 `is_available()` 自检，不可用时启动日志明确告警，并回退「不加密 + 显式警告」而不是写一半崩掉；
3. 补一条容器冒烟用例：起容器 → 存一个带 header 的请求 → 读回。

### 3.4 🔴 P0·依赖：声明错位 + 包管理器混用

实测证据：

```
E:\coding\api-tool\package.json          → { "dependencies": { "jsonrepair": "^3.15.0" } }
E:\coding\api-tool\node_modules\.pnpm   → 存在（pnpm 安装痕迹）
E:\coding\api-tool\frontend\node_modules\jsonrepair → 不存在
E:\coding\api-tool\frontend\package.json → 无 jsonrepair
```

- `RequestPane.vue:121,197` `import { jsonrepair } from 'jsonrepair'`：现在能跑，纯粹是因为 Node 解析会**向上冒泡**到仓库根的 `node_modules`。一旦在干净环境里 `cd frontend && npm ci`（`build-linux.sh:68` 就是这么干的）→ **构建失败**。
- 仓库根同时存在 pnpm 与 npm 两套产物，与历史上的「pnpm/npm 混用导致 node_modules 损坏」是同一类坑。

**建议**：删除根 `package.json` / `package-lock.json` / 根 `node_modules`，把 `jsonrepair` 加到 `frontend/package.json` 并只用 npm（或整体迁 pnpm 并统一 lockfile）。

### 3.5 🔴 P0·依赖：`mcp>=1.2.0` 与 `import httpx2` 不匹配

- `mcp_client.py:9` `import httpx2`，`_build_http_client()` 返回 `httpx2.AsyncClient`。
- `httpx2` 是真实包（Pydantic 维护的 httpx fork，**MCP Python SDK v2 才把传输层换成 httpx2**）；`pyproject.toml` 写的是 `mcp>=1.2.0` 与 `httpx>=0.27.0`，`launcher*.spec` 的 `hiddenimports` 也只列了 `httpx`。

→ 干净环境按声明的约束解析，很可能装到 `mcp` 1.x（依赖 httpx 而非 httpx2），此时 `backend.app.api.mcp` → `mcp_client` 在**应用启动阶段**就 `ModuleNotFoundError`，整个服务起不来；PyInstaller 打包也会漏收 `httpx2`。

**建议**：锁定 `mcp>=2`（并把 `httpx2` 显式声明为直接依赖），或在适配层按 SDK 版本分流；`hiddenimports` 同步补 `httpx2`、`httpx2._transports`。

### 3.6 🟠 P0·可用性：`/mcp`、`/llm`、`/history` 没有入口，`HttpWorkbench.vue` 是死代码

- `router/index.ts` 注册了 `/http`、`/mcp`、`/llm`、`/history` 四条路由，但 `layouts/MainLayout.vue` 只有一个 `<RouterView />`，**没有侧边栏/顶部导航**。
- 全前端搜索 `router.push|RouterLink|href="/llm|/mcp|/history"` 只命中 1 处：`HistoryView.vue:117 router.push('/http')`。
- 结论：`/llm`（LLM Playground）只能手敲地址；`/mcp`、`/history` 同样。而 `views/HttpWorkbench.vue`（8.3 KB）**没有被任何文件 import**。

**建议**（明确的产品决策点）：要么把「LLM Playground / MCP / 历史」做成工作台内的 tab 类型或抽屉（与现有 `kind: 'http'|'websocket'|'mcp'` 一致，再加 `'llm'`），要么补一个真正的左侧导航（集合树 + 功能入口分组）。同时删掉或复活 `HttpWorkbench.vue`。

### 3.7 🟠 P0·并发：单个模块级 `AbortController`，多 tab 互相覆盖

```
stores/workbench.ts:244  controller = new AbortController()
stores/workbench.ts:294  controller = null      // finally 无条件置空
stores/workbench.ts:298  function cancel() { controller?.abort() }
```

两个标签页同时发送：后一个会覆盖前者句柄；先完成的那次 `finally` 又把句柄清空 → 另一个 tab 的「停止」按钮点了没反应，且真正的上游请求继续跑。另外 `cancel()` 只能取消最后一个。

**建议**：`const controllers = new Map<string, AbortController>()`，按 `tab.id` 存取；`finally` 只删自己那一条。

### 3.8 🟠 P0·正确性：`replace("data:", "")` 篡改响应正文

`api/http.py:113`：

```python
frame_content = chunk_content.replace("data:", "")
```

`str.replace` 是**全局**替换：任何出现在正文里的 `data:` 都会被删掉（例如 JSON 字符串 `{"note":"data: 见附件"}` 会变成 `{"note":" 见附件"}`；某个普通 HTML/文本响应里出现 `metadata:` 也会被啃掉 `data:` 五个字符）。SSE 规范只要求处理**行首**的 `data:` 字段。

**建议**：`re.sub(r"(?m)^data:", "", chunk)`（且注意 `data:` 后的可选单空格），或更彻底——**下发原始字节/原始行**，把 SSE 语义解析完全交给前端（前端 `llmUtil.stripSsePrefix` 已经在做正确的事）。

同时建议把「原始字节」与「解析后的帧」分开：现在前端把 TCP chunk 直接当「SSE 事件帧」展示（`workbench.ts:274-277` → `ResponsePane.vue:66-94`），一帧被拆成半个 JSON 或一个 chunk 含多帧时，帧列表就是错的。

### 3.9 🔴 P0·安全：加密只覆盖 headers，Auth / 环境变量 / secrets 明文落库

`collection_store.py:45-50` 只处理：

```python
req["headers"]  →  加密
node["mcp_headers"]  →  加密
```

而同一个 `request` 对象里还有：

| 字段 | 现状 | 风险 |
|---|---|---|
| `request.auth.token / password / value`（Auth 页签） | **明文** | 最高频的敏感值反而没加密 |
| `environments[].vars`（环境变量） | **明文** | 通常就放着 API Key |
| `placeholders` / `docs` | 明文 | 可能含 token、内部接口说明 |
| `secrets` 表的 `value` | **明文**（`secrets.py:29-41` 直接存 DB） | 与「字段级加密」宣称不符 |
| `GET /api/secrets/{name}` | 直接返回明文（`api/secrets.py:24-29`） | 任何持 token 者（含 XSS）可拉全部密钥 |

**建议**

1. 加密范围扩到 `auth.*`、`environments`、`secrets.value`；对整棵子树做「敏感路径清单」而不是只认 headers。
2. `GET /api/secrets/{name}` 改为默认返回掩码，仅在「发送前服务端替换」路径内部解密；前端本来也不需要明文。
3. 备注：Linux 把 `Fernet` 密钥与数据库放在同一目录（`~/.api-tool/.master.key` + `api-tool.db`），**同一账号能读 db 就能读 key**，属于「防误看/防备份泄漏」而非「防本机攻击者」——建议在 README 里写清楚威胁模型，或支持口令派生（scrypt）的密钥。

### 3.10 🟠 P1·导入导出：Postman 导入会产生后端枚举外的 `body_type`

- `postman_io.py:113-127` 对 `raw + language` 映射出 `json / xml / html / text`；
- 后端 `schemas/http.py:20-24` 的 `BodyType` 只有 `none / json / raw / form-data`（Pydantic 枚举，非法值 → **422**）；
- 前端 `api/types.ts` 的 `BodyType` 同样只有 4 个，`RequestPane` 的 body 类型下拉里也没有 `xml/html/text`（会显示空白标签）。

→ 导入一个 Postman 里 body 语言为 XML / text 的请求，**发送时报 422**，且 UI 显示异常。

**建议**：导入时统一归一化为 `raw`（保留原文 + 记 `language` 附加字段用于高亮），或把 `xml/html/text` 正式加入前后端枚举并映射到 Monaco 语言。

其他导入导出缺口（对照 Postman v2.1 语义）：`auth` 块、`variable`（集合变量）、`description/docs`、`cookie`、`event`（tests/pre-request）全部丢弃；导出也不写这些。**并且前后端各有一套实现**（`utils/io.ts` 与 `postman_io.py`），已经出现行为差异（例如前端导出不写 `xml` 分支）。建议收敛到单一实现（前端只调后端 `/api/collections/export|import`）。

### 3.11 🟠 P1·压测统计：P95 索引算错

`bench_runner.py:296`：

```python
p95 = latencies[int(len(latencies) * 0.95) - 1]
```

- n=2 → `int(1.9)-1 = 0` → 取**最小值**（应接近最大值）；
- n=1 → `-1` → 取唯一值（偶然正确）；
- n=20 → index 18（第 19 个），偏差方向不稳定。

`bench_report.py` 里已有正确的 `_pct()`，两处却各算一套。

**建议**：统一复用 `bench_report._pct`（或用 `statistics.quantiles` / 线性插值），并给按时长分布画直方图。

### 3.12 🟠 P1·性能：流式拼接 O(n²) + 无 5 MB 上限

- `workbench.ts:276` `tab.body += data`：每个 chunk 都创建新字符串，长流（几十 MB）会明显卡顿；应按 `string[]` 累加 + 节流合并。
- 规格 `openspec/.../http-request-workbench/spec.md` 明确要求「响应体超过 5 MB 只渲染前 5 MB 并提示已截断」；`api/http.py:111` 只 `size += len(chunk)` 统计、不限制，前端也照单全收 → 大响应直接把内存和 Monaco 拖死。
- 大响应进 Monaco 前还应做**虚拟化/截断 + 下载原始文件**，而不是塞进编辑器。

### 3.13 🟠 P1·历史表裁剪每次全表扫描

`history_store.py:14-23` 每次插入都执行：

```sql
DELETE FROM t WHERE user_id=? AND id NOT IN (SELECT id FROM t WHERE user_id=? ORDER BY id DESC LIMIT ?)
```

数据量小时无感，但这是每发一次请求就跑一次的 O(n) 子查询。**建议**：`created_at` 建索引 + 只删溢出条数（`DELETE ... WHERE id <= (SELECT id ... OFFSET n LIMIT 1)`），并把上限（200/100/100）做成可配置。

### 3.14 🟠 P1·`/api/http/send` 是半成品路径

`api/http.py:31-46` 走 `http_client.send_request()`，而后者（`services/http_client.py`）**硬编码** `timeout=30.0, follow_redirects=False`，也**不解析 `__secret:`**。另外 `/stream` 里有一个反向问题：

```
api/http.py:55  content = resolve_refs(user_id, req.body)   # 解析了 secret
api/http.py:62  if body_type == JSON: content = req.body     # 又覆盖回原文
```

→ **JSON body 里的 `__secret:xxx` 不会生效**（raw 生效）。

**建议**：只保留一条发送实现（统一走 `stream`，`send` 内部复用），secret 解析放在「构造 content」之后的唯一出口。

### 3.15 🟠 P1·开发者文档不可访问；dev CORS 端口写错

- 生产模式下 `spa_fallback`（`app/__init__.py:97-104`）只放行 `api/`、`sse/`，其余一律返回 `index.html` → **`/docs`、`/openapi.json`、`/redoc` 全部被吞**。工具自身的 API 契约白白丢掉（而这正是「API 工具」的核心资产）。
- CORS 白名单写 `http://localhost:5173`（`__init__.py:49`），但 `vite.config.ts:15` 的 dev server 是 **8000**；README 又写 5173。三处不一致。

**建议**：`spa_fallback` 显式放行 `docs`、`openapi.json`、`redoc`；CORS 从环境变量读 origin 列表（默认 8000/5173 都放行）。

### 3.16 🟡 P1·LLM 侧：声明了三种 provider，只实现一种；流式 usage 恒为空

- `factory.py:11-13` 只注册 `openai`；`schemas/llm.py` 的 `ProviderType` 有 `ANTHROPIC/CUSTOM`，前端下拉也给了三项 → 选 anthropic/custom 调用直接 400 `未注册的 provider_type`。README 路线图「更多 LLM Provider 适配器（Anthropic 原生格式等）」已打勾，**实际未实现**。
- `api/llm.py:134` `usage: dict = {}` 全程未赋值；流式要拿到 usage 必须请求 `stream_options: {include_usage: true}` 并解析末尾帧 —— 现在既没请求也没解析 → **token 统计永远为空**（而这正是成本治理的前提）。
- 其它缺失（对照 2026 年 LLM 客户端基线）：system prompt 独立编辑、多轮上下文窗口预算与裁剪、`tool_calls`（含流式增量拼装）、结构化输出（`response_format` / JSON Schema）、多模态（图片/文件输入）、prompt 模板库、成本/延迟看板、批量评测（数据集 + 打分）。

### 3.17 🟡 P1·MCP 侧：每次调用重建连接，且只有一种传输

- `mcp_client.py` 的 `initialize / list_tools / call_tool` 各自 `async with` 新建 `httpx2.AsyncClient` + 新 session + 重新 `initialize` → 每次列工具/调工具都有完整的握手 + 建连开销，延迟显著。
- 仅支持 Streamable HTTP；`stdio`、旧版 SSE、WebSocket 均无。
- 未实现 `prompts` / `resources` 两类能力（只有 `tools`），也没有 `notifications`（`tools/list_changed`）处理、`resources` 订阅、OAuth 授权流程（MCP 规范近年已把 Authorization 纳入）。
- `tools/call` 只按 `input_schema` 做泛化表单，没有 `$ref` / `oneOf` / enum 的友好渲染，也没有「示例参数」生成。

**建议**：引入 session 池（`(server.url, headers_hash) → ClientSession`，带 TTL 与失效重建）；传输层抽象成 `transport: stdio|sse|http`；补 `prompts/list|get`、`resources/list|read`。

### 3.18 🟡 P1·WebSocket 能力偏薄

`WebSocketPane.vue` 直接 `new WebSocket(url)`：无自定义 header（浏览器 API 不支持，需服务端代理）、无 `subprotocol`、无二进制帧（ArrayBuffer/Blob）、无重连/心跳、无消息体格式化（JSON 美化/压缩）。且 `messages` 是组件内 `ref`，**切到别的 tab 再切回来，组件被销毁重建 → 连接断开、日志清空**。

### 3.19 🟡 P1·Collections 全量 PUT，团队协作会互相覆盖

`collections.ts:38-40` 每次改动（新建/改名/拖拽/保存请求/URL 解析回写）都 `PUT` 整棵树，后端 `save_collections()` 整行覆盖 `tree_json`。团队空间里两人同时编辑 → **后写者吞掉前者改动**（last-write-wins，无冲突检测、无版本号、无操作日志）。另外 `RequestBar.syncQueryToParams()` 在 URL 失焦时就会触发一次 `emit('save')` → 一次 PUT。

**建议**（分两步）：先加 `updated_at`/版本号做乐观锁 + 冲突提示；再演进为节点级 patch API（`PATCH /collections/{node_id}`）。

### 3.20 🟡 P1·前端体积：Monaco 全量 + Arco 全量

- `MonacoEditor.vue:8` `import * as monaco from 'monaco-editor'` → 打进 3.25 MB；`main.ts` 只注册了 `json` 与 `editor` 两个 worker，**却加载了全部语言包**。
- `main.ts:42-43` `app.use(ArcoVue)` 全量注册 + `arco.css` 全量引入（772 KB JS / 464 KB CSS）。
- Monaco 在首屏路由里被 `RequestPane` 直接依赖，没有懒加载。

**建议**：`monaco-editor/esm/vs/editor/editor.api` + 按需 `basic-languages`（json/markdown 足够）+ 动态 `import()`；Arco 用 `unplugin-vue-components` + `@arco-design/web-vue/es/...` 按需 + 仅引入用到的 CSS。预估首屏可降到 1.5 MB 以内。

### 3.21 🟡 P1·认证与会话的工程化

- token 存 `localStorage('api-tool.token')`（XSS 即取走；虽然用 Bearer 头天然免疫 CSRF，但仍是同类工具最常见的争议点）。
- **登录接口无任何速率限制 / 锁定策略**（密码策略很严，但可被在线暴力尝试；无 2FA、无失败审计）。
- `auth.py` 的 `resolve_token` 用 SQLite `datetime('now')`（空格分隔）与 Python `isoformat()`（含 `T`）做**字符串比较** —— 目前靠 `'T'(0x54) > ' '(0x20)` 偶然成立，属于脆弱实现，跨格式/跨年边界有风险。
- 头像以 base64 存 DB（20 KB × 用户数）。
