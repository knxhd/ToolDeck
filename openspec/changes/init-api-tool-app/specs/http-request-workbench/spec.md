## 新增需求

### 需求:HTTP 请求编辑与发送
系统必须提供 HTTP 请求编辑面板，允许用户配置请求方法、URL、Headers、Query Params、Body，并通过后端代理发出请求。请求方法必须至少支持 GET/POST/PUT/DELETE/PATCH/HEAD/OPTIONS。Body 编辑必须支持 JSON / raw text / form-data 三种格式。请求必须由后端代理发出（而非浏览器直接发出），以规避浏览器 CORS 与跨域限制。

#### 场景: 发送 GET 请求
- **当** 用户填入方法 GET、URL `https://api.github.com/users/octocat`，点击发送
- **那么** 后端通过 httpx 转发请求，返回状态码、响应头、响应体到前端响应面板

#### 场景: 发送 JSON Body 请求
- **当** 用户选择方法 POST，Body 类型 JSON，填入 `{"name":"test"}`，点击发送
- **那么** 后端按 `Content-Type: application/json` 转发，响应面板展示解析后的 JSON 高亮

#### 场景: 请求中转超时
- **当** 目标 URL 30 秒未响应
- **那么** 后端中断请求并返回 504 错误，前端提示「请求超时」

### 需求:请求历史持久化
系统必须把每次成功发送的请求（方法、URL、Headers、Body、响应摘要）保存到本地 `~/.api-tool/history.json`。历史列表必须支持搜索、重新加载、删除。历史条数必须限制在 200 条以内（超出按时间倒序淘汰最旧记录）。

#### 场景: 重发历史请求
- **当** 用户在历史列表点击某条记录
- **那么** 该请求的方法、URL、Headers、Body 自动填入编辑面板，用户可修改后重新发送

#### 场景: 清空历史
- **当** 用户点击「清空历史」并确认
- **那么** `history.json` 被清空，历史列表 UI 立即更新

### 需求:响应展示
系统必须展示响应的状态码、状态文本、响应头、响应体、耗时（毫秒）、响应体大小。响应体为 JSON 时必须语法高亮 + 可折叠节点。响应体超过 5MB 时必须只渲染前 5MB 并提示「内容过大已截断」。

#### 场景: 查看 JSON 响应
- **当** 后端返回 JSON 响应
- **那么** 响应面板使用 Monaco Editor 以 JSON 模式高亮显示，支持折叠根节点

#### 场景: 查看非 JSON 响应
- **当** 后端返回 HTML / 纯文本
- **那么** 响应面板以纯文本模式展示，不尝试解析

### 需求:响应 Header 与耗时展示
系统必须在响应面板独立区域展示所有响应头（key-value 表格）、状态码、总耗时、响应体字节数。耗时必须从后端发起请求到接收完最后一个字节计算。

#### 场景: 查看响应头
- **当** 请求完成
- **那么** 响应头区域以表格列出所有 header，支持搜索过滤
