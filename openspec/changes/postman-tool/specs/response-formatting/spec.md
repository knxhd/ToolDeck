## 新增需求

### 需求:响应格式化 Tab 切换
系统必须为 HTTP 和 SSE 响应提供多种格式化视图 Tab，允许用户切换查看。

#### 场景:默认选中格式化 Tab
- **当** 响应到达
- **那么** 系统根据 Content-Type 自动选择最佳格式化 Tab
- JSON 响应默认选中 JSON Tab，HTML 响应默认选中 HTML Tab，以此类推

#### 场景:切换格式化 Tab
- **当** 用户点击不同的格式化 Tab（Raw / JSON / HTML / XML / TXT）
- **那么** 响应内容立即以对应格式渲染显示

### 需求:JSON 格式化
系统必须对 JSON 格式的响应进行美化缩进显示。

#### 场景:JSON 响应美化
- **当** 用户选中 JSON Tab 且响应体是合法 JSON
- **那么** 系统以 2 空格缩进美化显示 JSON 内容

#### 场景:非法 JSON 处理
- **当** 用户选中 JSON Tab 但响应体不是合法 JSON
- **那么** 系统显示原始文本，并提示"响应不是合法 JSON"

### 需求:HTML 格式化
系统必须对 HTML 格式的响应进行渲染或美化显示。

#### 场景:HTML 渲染预览
- **当** 用户选中 HTML Tab 且响应体是 HTML
- **那么** 系统提供渲染预览（iframe 嵌入）和源码美化两种子视图

### 需求:XML 格式化
系统必须对 XML 格式的响应进行美化缩进显示。

#### 场景:XML 响应美化
- **当** 用户选中 XML Tab 且响应体是合法 XML
- **那么** 系统以缩进美化显示 XML 内容

### 需求:TXT 直出
系统必须提供纯文本直出视图。

#### 场景:Raw TXT 显示
- **当** 用户选中 Raw Tab
- **那么** 系统以等宽字体显示响应体原始文本，不做任何格式化

### 需求:响应元信息显示
系统必须在结果区域顶部显示响应元信息。

#### 场景:显示响应状态
- **当** 响应到达
- **那么** 显示 HTTP 状态码、状态文本、响应耗时、响应大小
- **当** 响应 Headers 可用
- **那么** 提供单独的 Headers Tab 查看所有响应头
