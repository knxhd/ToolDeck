## 新增需求

### 需求:多 Tab 工作区管理
系统必须支持同时打开多个请求 Tab，每个 Tab 拥有独立的请求状态。

#### 场景:创建新 Tab
- **当** 用户点击 "+" 按钮
- **那么** 创建一个新的请求 Tab，初始为空白状态
- **当** 新 Tab 创建后
- **那么** 自动切换到新 Tab，Tab 标题默认为 "Untitled"

#### 场景:切换 Tab
- **当** 用户点击某个 Tab
- **那么** 工作区切换到该 Tab 的请求构造器和结果展示区
- **当** 切换 Tab 时
- **那么** 其他 Tab 的状态保持不变（包括正在进行的请求）

#### 场景:关闭 Tab
- **当** 用户点击 Tab 的关闭按钮
- **那么** 该 Tab 及其所有状态被销毁
- **当** 关闭的是最后一个 Tab
- **那么** 自动创建一个新的空白 Tab

#### 场景:Tab 标题更新
- **当** 用户输入 URL 并离开输入框
- **那么** Tab 标题更新为 URL 的域名部分（如果是 Untitled）
- **当** 用户从 Collection 打开一个请求
- **那么** Tab 标题更新为请求名称

### 需求:Tab 独立状态
每个 Tab 必须维护独立的请求构造器状态和结果状态。

#### 场景:Tab 间状态隔离
- **当** Tab A 正在接收 SSE 流，用户切换到 Tab B
- **那么** Tab B 显示自己的请求状态，不受 Tab A 影响
- **当** 用户切回 Tab A
- **那么** Tab A 显示原始的 SSE 流进度和结果

#### 场景:请求并发
- **当** Tab A 和 Tab B 同时发送请求
- **那么** 两个请求独立进行，互不阻塞
- **当** 其中一个请求完成
- **那么** 只更新对应 Tab 的结果展示区
