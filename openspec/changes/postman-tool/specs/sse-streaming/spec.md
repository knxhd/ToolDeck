## 新增需求

### 需求:SSE 流式响应透传
系统必须通过后端代理将上游 SSE 响应逐帧透传给前端，不做协议解析。

#### 场景:上游返回 SSE 响应
- **当** 后端发起流式请求，上游返回 content-type: text/event-stream
- **那么** 后端使用 StreamingResponse 逐帧 yield 原始 SSE 帧
- **当** 前端收到 SSE 帧
- **那么** 原始 payload 字符串立即显示在原始帧视图中

#### 场景:上游返回普通非流式响应
- **当** 后端发起流式请求，上游返回普通 HTTP 响应
- **那么** 后端将响应包装成 SSE 帧：data: {"type":"frame","data":"<body>"} 后跟 data: {"type":"done"}

#### 场景:上游断连处理
- **当** 上游 SSE 连接断开（无论正常关闭还是异常）
- **那么** 后端在 finally 块中发送 data: {"type":"done"} 帧
- **当** 前端收到 type=done 帧
- **那么** 标记流结束，停止接收

### 需求:SSE 原始帧视图
系统必须为 SSE 响应提供原始帧实时显示视图。

#### 场景:实时显示 SSE 帧
- **当** SSE 流正在接收
- **那么** 每收到一帧，原始 payload 字符串（data: 后面的内容）立即追加显示
- **当** 流结束
- **那么** 显示停止，保留所有已接收的帧历史

#### 场景:区分帧类型
- **当** 前端收到 type=frame 的 SSE 帧
- **那么** 提取 data 字段（原始 payload 字符串）显示
- **当** 前端收到 type=done 的 SSE 帧
- **那么** 不在原始帧视图中显示（仅用于标记结束）
